# Architecture Decision Records

Create ADRs as `adr-001-short-title.md`, then increment the number. Include the date, status (`Proposed`, `Accepted`, `Superseded`, or `Rejected`), context, options, decision, rationale, consequences, and validation. Link to affected PRD sections and GitHub issues.

Use an ADR to justify changes to the proposed schema described in the PRD, as required by the challenge. Do not treat a proposal as accepted until it has been decided. When a decision changes, link the replacement ADR and update the old status.
